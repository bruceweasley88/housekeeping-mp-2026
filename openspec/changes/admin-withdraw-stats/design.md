## Context

当前提现管理页面（`finance/bill_withdraw.vue`）仅有固定的"已提取"和"已拒绝"汇总卡片，统计数据不区分时间周期，且缺少待提现金额和佣金收入维度。后端 `BillController::summary()` 仅做简单的 WHERE 聚合，无周期计算逻辑。

系统已有的佣金/手续费配置：`withdraw_fee_rate`（提现手续费率，默认 3%）存储在 `ConfigService` 的 `fee` 分组中。佣金收入 = 已提取金额 × 手续费率。

## Goals / Non-Goals

**Goals:**
- 提供平台维度的周/月/年提现统计视图，涵盖提现、拒绝、待提现、佣金四大指标
- 提供用户维度的周/月/年提现统计视图，按用户聚合并支持展开明细
- 复用现有 `Bill` 模型和 `BillEnum` 枚举，保持架构一致性

**Non-Goals:**
- 不修改现有提现管理页面的功能
- 不新增数据库表或字段
- 不实现导出功能（后续迭代）
- 不实现自定义时间范围（仅周/月/年三档）

## Decisions

### 1. 周期计算方式：后端 SQL WHERE 筛选

**选择**: 后端接收 `period` 参数（`week`/`month`/`year`），根据当前时间计算 `start_time` 和 `end_time`，在 SQL 查询中做 WHERE 筛选。

**备选方案**: 前端传 `start_time`/`end_time`，后端透传筛选。
**理由**: 周/月/年的起止时间计算逻辑固定，由后端统一处理可避免前端传参不一致，同时前端仍可保留搜索条件覆盖。

### 2. 页面结构：两个独立页面

**选择**: 在"财务管理"菜单下新增"提现统计"子菜单，包含"平台统计"和"用户统计"两个独立页面（Tab 切换或平级子菜单）。

**备选方案**: 在现有提现管理页面中添加 Tab。
**理由**: 独立页面更清晰，避免现有提现管理页面过度膨胀，路由也更易维护。采用平级子菜单方式。

### 3. 佣金收入计算：查询时动态计算

**选择**: 佣金 = 已提现金额（STATUS_SETTLED）× withdraw_fee_rate，在统计查询时动态计算。

**备选方案**: 在 Bill 表中增加 `fee` 字段记录每次提现的手续费。
**理由**: 当前 Bill 表未存储手续费，且手续费率可能随时间调整。动态计算实现简单，无需改表。若后续需要精确到单笔的手续费记录，再考虑加字段。

### 4. 用户统计的数据加载：分页 + 展开明细

**选择**: 用户统计主列表分页展示每个用户的汇总数据，点击某行展开显示该用户在周期内的提现明细列表。

**备选方案**: 一次性加载所有用户及明细。
**理由**: 用户数量可能较多，分页 + 按需展开明细可避免一次性查询大量数据。

## Risks / Trade-offs

- **[手续费率历史变更]** → 佣金统计使用当前费率而非历史费率，可能与实际有偏差。可在统计页面上标注"基于当前手续费率计算"。
- **[大数据量性能]** → 周/月/年统计需要全量聚合查询。通过 `create_time` 索引 + `type` + `status` 组合条件控制扫描范围。若数据量持续增长，后续可考虑增加缓存或预聚合表。
