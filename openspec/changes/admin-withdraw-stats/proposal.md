## Why

当前提现管理页面仅有简单的"已提取"和"已拒绝"汇总卡片，缺乏按时间周期（周/月/年）维度的统计分析能力，管理员无法快速了解平台提现趋势、佣金收入和各用户的提现行为，不利于财务运营决策。

## What Changes

- 新增**平台统计**页面：支持按周/月/年切换统计周期，展示平台总提现笔数与金额、总拒绝笔数与金额、待提现金额、平台佣金收入金额
- 新增**用户统计**页面：支持按周/月/年切换统计周期，以用户为单位聚合展示各人的提现笔数与金额、拒绝笔数与金额，并支持展开查看每条提现明细
- 后端新增平台维度的提现统计 API（含周期筛选、佣金计算）
- 后端新增用户维度的提现统计 API（含周期筛选、用户聚合、明细展开）

## Capabilities

### New Capabilities
- `withdraw-platform-stats`: 平台维度的提现统计能力，支持周/月/年周期筛选，返回平台总提现笔数/金额、拒绝笔数/金额、待提现金额、佣金收入
- `withdraw-user-stats`: 用户维度的提现统计能力，支持周/月/年周期筛选，按用户聚合提现数据并支持展开查看明细记录

## Impact

- **后端**: `BillController` 新增 2 个统计接口，复用 `Bill` 模型和 `BillEnum` 枚举
- **Admin 前端**: `finance` 目录下新增 2 个页面组件，`api/finance.ts` 新增 2 个 API 方法，路由配置新增 2 个页面
- **数据**: 依赖 `ls_bill` 表现有数据，佣金收入通过 `withdraw_fee_rate` 配置值与提现金额计算得出（非存储字段）
- **无破坏性变更**: 纯新增功能，不影响现有提现管理页面
